## 1. Architecture & Design

### 1.1 Dual Storage Architecture
The system dynamically toggles between persistent cloud storage and local development storage based on environment variables:

| Environment | Variable Configuration | Storage Backend Class | Location |
| :--- | :--- | :--- | :--- |
| **Production** | `USE_S3=True`<br>`AWS_STORAGE_BUCKET_NAME=...` | `app.storage_backends.MediaStorage` (subclass of `S3Boto3Storage`) | Cloudflare R2 / AWS S3 (`media/` prefix) |
| **Development** | `USE_S3=False` | `django.core.files.storage.FileSystemStorage` | Local filesystem (`backend/media/`) |

### 1.2 Unified Protected Download Pipeline
All media URLs generated by Django models (`outline_file`, `deliverable_file`, `attachment`, `screenshot`) route through the relative prefix `/media/<path>`. 

Direct public URLs to the Cloudflare R2 / S3 bucket are **never** returned to client browsers. All downloads pass through Django's `SecureMediaDownloadView`:

```
[Browser / Mobile Client]
         │
         ▼  (HTTP GET with Bearer JWT token)
[SecureMediaDownloadView]
         │
         ├── 1. Check Authentication (JWT validation via AccessToken)
         ├── 2. Path Traversal Validation (reject '..', null bytes, leading slashes)
         ├── 3. RBAC & Group Isolation (verify user belongs to supervisor group)
         ├── 4. Candidate Key Resolution (R2 path / fallback to local disk)
         │
         ▼
[File Stream Response (200 OK)]
(Content-Type, Content-Length, Content-Disposition RFC 5987/6266 UTF-8)
```

## 2. Security & Access Control (RBAC)

### 2.1 Access Matrix

| User Role | Outline Reviews | Progress Reports | Deliverables | Group Chat Attachments | Committee Templates |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Admin / Coordinator** | Read / Write | Read / Write | Read / Write | Read / Write | Read / Write |
| **Assigned Supervisor** | Read / Write | Read / Write | Read / Write | Read (Own Group Only) | Read |
| **Enrolled Student** | Read (Own Project) | Read (Own Project) | Read (Own Project) | Read (Own Group Only) | Read |
| **Unassigned Student / External** | ❌ 403 Forbidden | ❌ 403 Forbidden | ❌ 403 Forbidden | ❌ 403 Forbidden | ❌ 403 Forbidden |
| **Anonymous / Expired Token** | ❌ 401 Unauthorized | ❌ 401 Unauthorized | ❌ 401 Unauthorized | ❌ 401 Unauthorized | ❌ 401 Unauthorized |

### 2.2 Path Traversal & Sanity Checks
- `is_safe_relative_path(path)` rejects any attempt containing `..`, absolute paths (`/etc/passwd`), null bytes (`\x00`), or Windows drive letters (`C:`).
- Unauthorized path attempts immediately return `404 Not Found` without disclosing file existence or server directory structures.

### 2.3 Non-ASCII / Vietnamese Filenames
Files uploaded with Vietnamese diacritics (e.g. `Báo_cáo_đồ_án_tốt_nghiệp.pdf`) are served with dual `Content-Disposition` headers compliant with RFC 5987 / RFC 6266:
```http
Content-Disposition: attachment; filename="Bao_cao_do_an_tot_nghiep.pdf"; filename*=UTF-8''B%C3%A1o_c%C3%A1o_%C4%91%E1%BB%93_%C3%A1n_t%E1%BB%91t_nghi%E1%BB%87p.pdf
```
This guarantees flawless file downloads on all legacy and modern browsers without encoding corruption.

## 4. Monitoring & Error Troubleshooting

### 4.1 HTTP Status Codes & Diagnostics

| Status Code | Cause | Diagnostic Action |
| :--- | :--- | :--- |
| **200 OK** | File successfully validated and streamed | Normal operation. |
| **401 Unauthorized** | Missing or expired JWT Access Token | Client must refresh JWT token using `/api/token/refresh/` or re-authenticate. |
| **403 Forbidden** | User not a member of the group/project | Verify student-supervisor assignment in `GraduationProject` or `SupervisorGroupChatMessage`. |
| **404 Not Found** | File does not exist in storage or DB | Check file name, verify migration status via `migrate_media_to_s3`. |
| **503 Service Unavailable** | Cloud storage (R2/S3) connection error | Check R2 credentials, endpoint URL, network connectivity, or Render outbound egress. |

### 4.2 Handling S3 Connection Errors (503)
When Cloudflare R2 or AWS S3 is unreachable, `SecureMediaDownloadView` logs the exception and returns:
```json
{
  "error": "Storage service temporarily unavailable. Please retry shortly."
}
```
If 503 errors persist:
1. Check `AWS_S3_ENDPOINT_URL`: Ensure format is `https://<account_id>.r2.cloudflarestorage.com` (no trailing slash).
2. Check `AWS_S3_ADDRESSING_STYLE`: Ensure `path` is set for Cloudflare R2.
3. Check `AWS_STORAGE_BUCKET_NAME`: Ensure bucket exists in Cloudflare R2.
4. Verify Render service outbound network status.

## 5. Maintenance Procedures

### 5.1 Routine Sync
To sync newly uploaded local media files to Cloudflare R2 during gradual deployment:
```bash
python manage.py migrate_media_to_s3 --verify-checksum
```

### 5.2 Emergency Cloud-to-Local Backup
To pull a full snapshot of all active cloud files to local disk:
```bash
python manage.py migrate_media_to_s3 --from-s3-to-local --dest-dir=/backup/media --verify-checksum
```
